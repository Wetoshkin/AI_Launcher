# AI Launcher Studio — полный редизайн: дизайн-спецификация

- Дата: 2026-06-12
- Статус: принято к реализации (пользователь работает автономно, утверждение по ходу не требуется)
- Репозиторий: `Wetoshkin/AI_Launcher`, рабочая копия `D:\Nextcloud\Ai\Projects\AI Laucher\repo`

## 1. Зачем

Текущее десктоп-приложение (сделано Codex) собирается и проходит 224 теста, но **в живую не работает как продукт**: DPI-неосознанная вёрстка переполняется на масштабе 150%, вся логика свалена в один `HomeViewModel.cs` (73 КБ) и один экран `HomeView.axaml` (45 КБ), «мастер» из 9 шагов — это декоративные чипы, а не реальный поток. Кнопки часто не дают понятного результата.

Backend (`Launcher.Core/Runtimes/Models/Agents`) — добротный, разбит на мелкие тестируемые файлы, и **переиспользуется**. Переписывается **только Desktop-слой**, плюс добавляются недостающие доменные части (мульти-GPU probe, движок конфликтов, провайдеры онлайн-чата).

### Целевой пользователь
Два полюса, оба должны быть счастливы:
- **Новичок** «вообще не шарит»: пара кнопок → говорит с локальной или онлайн-нейросетью. Может не иметь ни модели, ни runtime.
- **Профи**: полный доступ ко всем флагам llama-server, KV-типам, MTP/speculative, мульти-инстансу.

### Критерии успеха
1. Реально работает: всё нажимается и даёт понятный результат. Проверяется не только тестами, но и запуском приложения с визуальным осмотром (скриншот каждого экрана).
2. Красиво и DPI-корректно на 100/125/150/175%.
3. Понятно: каждая «страшная» фича (TurboQuant, MTP, KV-cache, speculative, контекст) снабжена объяснением «что это и зачем тебе».
4. Безопасно по настройкам: движок конфликтов предупреждает о несовместимых/тормозящих комбинациях до запуска.
5. Наглядно по железу: реальная диаграмма загрузки модели в память одной/двух карт + системную RAM, с предупреждением о переполнении.
6. Работает на железе без NVIDIA/RTX: авто-выбор Vulkan/CPU; CUDA — только если есть NVIDIA.
7. Никаких упоминаний исходного форка и сторонних контрибьюторов. Авторы: только пользователь (Wetoshkin) и Claude.

## 2. Что переиспользуем, что добавляем, что выкидываем

**Переиспользуем (backend как есть, при необходимости расширяем):**
- `Launcher.Core`: `WizardRouteService`/`WizardStep`/`LaunchWizardState`, `LaunchProfile`/`LauncherSettings`/`ProfileSerializer`, `KvCacheSettings`/`MtpSettings`, `DecodingPresetCatalog`, `LaunchGuard`, `LaunchReviewBuilder`, `ParameterHelpCatalog` (расширяем).
- `Launcher.Runtimes`: `Memory/*` (MemoryEstimator, GpuMemoryForecaster, ContextRecommender, KvCacheProfile), `LlamaCpp/*` (command builder, help parser, release/download/install, compatibility), `Ports/*`, `Processes/*`, `Startup/*`, `Status/*`, `Ollama/*`.
- `Launcher.Models`: локальный каталог GGUF, Hugging Face поиск/скачивание/очередь.
- `Launcher.Agents`: command builders OpenCode/Kilo/Claw/Aider, CLI discovery, project config writers.

**Добавляем (новые доменные модули/сервисы):**
- `Launcher.Runtimes/Hardware`: **мульти-вендорный GPU probe** (Intel Arc/AMD/NVIDIA + iGPU + системная RAM) — сейчас probe только NVIDIA (`NvidiaSmiGpuProbe`). Нужен `WindowsGpuProbe` через WMI/DXGI + RAM из `Win32_ComputerSystem`. Модель `MemoryEstimate` расширяется до раскладки по устройствам.
- `Launcher.Core/Compatibility`: **движок конфликтов настроек** `SettingsConflictEngine` — единая точка проверок (MTP↔модель/ runtime, TurboQuant↔runtime, MTP↔TurboQuant, контекст↔нативный контекст модели, KV-тип↔runtime, контекст↔память, CUDA-runtime↔не-NVIDIA). Возвращает список `ConflictFinding{ Severity(Info/Warning/Error), Title, Plain explanation, Suggested fix }` на русском. Поглощает существующий `RuntimeCompatibilityService`.
- `Launcher.Online` (новый проект): **провайдеры онлайн-моделей** — реестр (OpenAI / Anthropic / OpenRouter / custom OpenAI-совместимый), хранение API-ключей, прокси-aware `HttpClient` (Hiddify `http://127.0.0.1:12334`), стриминговый чат-клиент (OpenAI-совместимый + Anthropic Messages API).
- **Расширенный реестр аргументов llama-server** (по образцу зрелого набора флагов): generation (temp/top-k/top-p/penalties/reasoning), advanced (flash-attn/cont-batching/mlock/mmap/webui), с help-текстом и уровнем риска — питает «Эксперт»-режим и движок конфликтов.

**Выкидываем:**
- Весь `Launcher.Desktop` UI-слой (god-объекты `HomeViewModel`/`HomeView`) — переписываем с нуля на multi-view MVVM.
- Любые ссылки/упоминания исходного форка в коде, README, docs, LICENSE-заголовках. Чистим контрибьюторов.

## 3. Архитектура Desktop (новая)

MVVM на Avalonia 11 + `CommunityToolkit.Mvvm`. Навигация через `ShellViewModel` с активной страницей; никаких god-объектов — одна страница = один ViewModel + один View, каждый < ~400 строк.

```
ShellView (окно, боковая навигация + статус-бар железа)
├── HomeViewModel            — хаб: статус системы + большие действия + онбординг первого запуска
├── LaunchWizardViewModel    — пошаговый мастер (semi-auto), хост для step-VM:
│     ├── ModeStepViewModel        (локально/онлайн × чат/сервер/агент)
│     ├── ModelStepViewModel       (локальный каталог + HF + авто-рекомендация под железо)
│     ├── RuntimeStepViewModel     (детект/выбор/скачать; авто CPU/Vulkan/CUDA)
│     ├── TuningStepViewModel      (контекст/KV/MTP/speculative + help + диаграмма памяти + конфликты)
│     ├── ProviderStepViewModel    (онлайн: провайдер + ключ/прокси)
│     ├── ReviewStepViewModel      (полный предпросмотр команды + предупреждения + экспорт .bat/JSON)
│     └── LaunchStepViewModel      (live-лог, статус endpoint, стоп/перезапуск)
├── ChatViewModel            — встроенный чат (локальный llama-server ИЛИ онлайн-провайдер), стриминг
├── ModelsViewModel          — каталог GGUF + HF поиск/скачивание/очередь
├── RuntimesViewModel        — установленные сборки llama.cpp, скачать/обновить/переключить версию
└── SettingsViewModel        — глобальные настройки, прокси, профили, режим Новичок/Эксперт
```

**Ключевые переиспользуемые UI-контролы:**
- `HardwareMemoryView` — кастомный контрол: рисует бары устройств (каждая GPU VRAM + системная RAM), накладывает блоки «веса модели / KV-cache / overhead», красит «влезает/впритык/переполнение», показывает per-device раскладку при 1 или 2 картах. Источник данных — расширенный `MemoryEstimate` + мульти-GPU probe.
- `ConflictPanel` — список findings из `SettingsConflictEngine` с иконкой severity, заголовком, объяснением и кнопкой «исправить».
- `HelpHint` — иконка «?» рядом с любым параметром, тянет текст из `ParameterHelpCatalog`.

**DPI/респонсив:** никаких фиксированных пиксельных размеров под конкретный экран; использовать `Viewbox`/`Grid` со звёздными размерами, `MinWidth/MinHeight` вместо фикс, тестировать на 100/125/150/175%. Базовое окно 1100×720, корректно скроллится и не обрезается.

**Режим Новичок/Эксперт:** глобальный тумблер. В режиме Новичок шаг Tuning показывает только пресеты («Быстро» / «Сбалансированно» / «Качество») + диаграмму памяти; все сырые флаги скрыты за «Показать продвинутые». В Эксперт — полный набор аргументов из реестра.

## 4. Сценарии (happy paths)

### 4.1 Локальный чат для новичка (главный сценарий)
1. Первый запуск → Home показывает: железо (CPU/GPU/RAM детектится сам), и «у тебя пока нет ни модели, ни runtime — давай поставим».
2. Нажал «Поговорить с ИИ локально».
3. Мастер (semi-auto, подсказки, выбор за пользователем):
   - **Runtime**: приложение определило Intel Arc → рекомендует Vulkan-сборку, кнопка «Скачать рекомендованный». (CUDA не предлагается без NVIDIA.)
   - **Модель**: рекомендует 1–2 небольшие модели под объём памяти (напр. Qwen2.5 3B Q4_K_M), кнопка «Скачать». Если модель уже есть — видна в каталоге.
   - **Tuning**: пресет «Сбалансированно» подобран автоматически; диаграмма памяти показывает, что влезает; конфликтов нет.
   - **Review**: показывает реальную команду; «Запустить».
4. Поднимается `llama-server`, ждём `GET /v1/models`, открывается встроенный **Чат**. Новичок печатает — отвечает локальная модель.

### 4.2 Онлайн-чат
- «Поговорить с ИИ онлайн» → выбрать провайдера (OpenAI/Anthropic/OpenRouter) → ввести API-ключ (хранится локально) → опционально включить прокси Hiddify → встроенный чат стримит ответы.

### 4.3 Кодинг-агент (локально или онлайн через прокси)
- «Кодинг-агент» → выбрать проект (папку) → агент (OpenCode/Kilo/Claw/Aider, видно что установлено в PATH) → источник модели: локальный llama-server ИЛИ онлайн-провайдер через прокси → пишется конфиг проекта (`opencode.json`/`kilo.jsonc`) с нужным provider model id → запускается сервер (если локально) → запускается CLI агента.

### 4.4 Сервер-endpoint (профи)
- «Запустить сервер модели» → модель + runtime + порт + полный tuning → llama-server как OpenAI-совместимый endpoint для внешних клиентов; можно открыть встроенный WebUI llama-server в браузере.

## 5. Движок конфликтов (правила, на основе ресёрча)

Severity и тексты — на русском, с объяснением и предложением фикса.

- **MTP без MTP-модели** → Error: «MTP (`--spec-type draft-mtp`) требует модель с MTP/NextN-головой (напр. Qwen3.6 MTP, Gemma 4 MTP). У выбранной модели её нет». Фикс: выключить MTP или выбрать MTP-модель.
- **MTP/TurboQuant без поддерживающего runtime** → Error: «Текущая сборка llama.cpp не поддерживает эту фичу». Фикс: скачать TurboQuant-сборку / обычную сборку.
- **MTP может замедлять** → Warning: на части бэкендов MTP даёт net loss по скорости. Фикс: сравнить с выключенным.
- **Контекст > нативного контекста модели** → Warning: «Модель обучена на N токенов; больше — через RoPE-scaling, возможна потеря качества». Фикс: вернуть к нативному.
- **KV-тип (turbo2/3/4) на не-TurboQuant runtime** → Error. Фикс: turbo-тип только на TurboQuant-сборке.
- **Контекст/модель не влезает в память** → Warning/Error: оценка через MemoryEstimator превышает свободную память → выгрузка на CPU/диск, сильное замедление. Фикс: меньше контекст, агрессивнее KV-квант, меньше `-ngl`, модель меньше.
- **CUDA-сборка на машине без NVIDIA** → Error: «CUDA-сборка не запустится без NVIDIA GPU». Фикс: Vulkan или CPU сборка.

## 6. Тестирование

- **Юнит-тесты** на каждый новый сервис: мульти-GPU probe (парсинг WMI-вывода), `SettingsConflictEngine` (таблица правил), онлайн-провайдеры (сборка запроса, парсинг стрима, прокси), расширенный реестр аргументов, раскладка памяти по устройствам.
- **ViewModel-тесты** на навигацию мастера, доступность кнопок (то, что у Codex «не нажималось» — закрыть тестами на `CanExecute` и переходы состояний), применение пресетов, обновление диаграммы памяти и панели конфликтов при смене настроек.
- **Визуальная проверка глазами**: после каждого UI-среза запускать приложение, делать скриншот окна (есть рабочий способ через PrintWindow/CopyFromScreen), осматривать вёрстку на 150% DPI, фиксировать дефекты и чинить. Зелёные тесты не считаются доказательством готовности UI.
- **Smoke сквозного запуска** со stub `llama-server`: endpoint-only, agent+endpoint, занятый порт, отсутствующий CLI/runtime/модель.
